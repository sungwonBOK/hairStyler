# 교체 가능한 이미지 편집 설계

## 공통 호출

서버 라우트 → editHairstyle(input, context) → 선택한 어댑터 → 외부 API.

`worker/hairstyle/types.ts`가 공통 계약이다. 화면에서는 업체명, API 키, 모델별 옵션을 전달하지 않는다. 서버 환경 설정으로 업체와 모델을 고르고, 서버에서 비밀 키를 주입한 어댑터만 등록한다.

입력: 원본 또는 이전 결과의 이미지 바이트·MIME, 선택한 스타일, 추가 수정 요청.
출력: 이미지 바이트·MIME, 실제 사용 업체·모델.

```ts
const result = await editHairstyle(
  { photo, style: selectedStyle.name, instructions: '컬을 조금 약하게' },
  { provider: config.provider, model: config.model, adapters, signal: request.signal },
);
```

## 어댑터의 책임

| 업체 키 | 모듈의 책임 | 이번 상태 |
| --- | --- | --- |
| google | Gemini 이미지 편집 요청·응답 변환. Nano Banana 2.1의 실제 API 식별자는 공식 API 확인 후 설정 | 다음 단위에서 구현 |
| fal | 업로드·작업 큐·폴링·임시 URL 이미지 회수, 공통 바이너리 변환 | 계약만 준비 |
| openai | 이미지 편집 multipart 요청·응답 변환 | 계약만 준비 |

이번 단위에서는 공통 진입점과 어댑터 인터페이스만 구현했다. 외부 이미지 업체 구현체는 아직 없으며, 미등록 업체는 명확하게 실패한다. 작동하는 것처럼 보이는 빈 구현체는 등록하지 않는다.

## 변경·확장 규칙

- 모델별 프롬프트·해상도·파일 전달 방식·큐 동작은 어댑터 내부에 둔다.
- fal의 비동기 작업은 어댑터가 완료까지 기다린다. 장시간 작업이 실제로 필요해지면 별도의 작업 조회 API와 만료 정책을 추가한다. 지금은 DB·R2를 추가하지 않는다.
- 공통 함수가 파일 크기·입력값·출력값을 검사하고 오류를 표준화한다.
- 어댑터는 전달된 AbortSignal을 모든 업로드·폴링·요청에 적용한다. 공통 제한은 90초다. 공급자가 취소 후에도 처리한 작업은 비용이 발생할 수 있다.
- 자동 재시도나 다른 업체로의 자동 전환은 하지 않는다. 중복 과금과 사진의 예상 밖 제3자 전송을 피한다.
- 프론트엔드와 공통 함수는 업체 URL·비밀 키·원시 응답을 다루지 않는다. 서버 조립 단계에서만 키를 어댑터에 넣는다.
- 실제 얼굴 사진을 보내는 시점에 업체·목적·보관 정책 동의를 확인한다. 사진과 결과를 요청 로그에 남기지 않는다.
- 어댑터 계약 테스트는 공통 입출력과 업체 선택·오류를 확인하고, 각 업체를 붙일 때 실제 HTTP 규격 테스트를 별도로 추가한다.

## 추천과 이미지 편집 분리

추천 LLM은 `worker/gemini.ts`로 분리돼 있다. 이미지 편집 업체를 바꾸어도 Gemini 추천에는 영향이 없다. 추후 추천 업체 교체가 필요하면 추천에도 별도의 인터페이스를 적용한다.
